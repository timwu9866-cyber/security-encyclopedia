# 通用网络安全节点模型 · 调研清单与造型规范

> 概念展示用,不对应任何真实产品或商标。数据源:`js/nodelib.js`(`NODELIB.SPEC`),由 `node tools/export_nodespec.js` 生成本文件与 `data/nodespec.json`。在线预览:`nodes.html`。

## 1. 类别与颜色

| 类别 | 英文 | 夜间色 | 日间色 | 数量 |
|---|---|---|---|---|
| 网络设备 | Network | `#1fe85a` | `#0c7a32` | 6 |
| 办公设备 | Office / Endpoint | `#2f8fff` | `#1a6fd4` | 6 |
| 安全设备 | Security | `#f5c518` | `#c9a010` | 9 |
| 服务器 / 云 | Server / Cloud | `#c9a0ff` | `#7a48c8` | 6 |
| 终端 / IoT / 工控 | IoT / ICS | `#ff6bcb` | `#c02098` | 5 |
| 攻击者 / 外部 | Threat / External | `#ff3b4e` | `#c01830` | 5 |

合计 **37** 种。必选三类:网络设备=绿、办公设备=蓝、安全设备=黄;补充三类:服务器/云=紫、终端/IoT/工控=品红、攻击者/外部=红(与事件大全"攻击"语义红一致)。

## 2. 节点清单

角色说明:**源**=事件发起方,**目标**=被攻击对象,**防护**=防守措施,**路径**=流量途经的中间设施。

### 网络设备(Network)

| 类型 | 名称 | 尺寸 | 缩写 | 用途 | 造型要点 | 常见角色 |
|---|---|---|---|---|---|---|
| `router` | 路由器 / Router | M | RT | 在不同网段/运营商之间转发数据包、维护路由表。 | 扁平机身 + 后部两根竖直天线,正面一排指示灯。 | 路径、目标 |
| `switch` | 交换机 / Switch | M | SW | 在同一局域网内按 MAC 地址转发,连接大量终端端口。 | 超长 1U 薄机身,正面两排小方口阵列。 | 路径、目标 |
| `coreswitch` | 核心交换机 / Core Switch | L | CS | 园区/机房汇聚核心,承载大部分东西向流量。 | 宽机箱,竖直插卡槽位(竖向条纹)+ 顶部风扇格栅。 | 路径、目标 |
| `ap` | 无线 AP / Wireless AP | S | AP | 为终端提供 Wi-Fi 接入,常见于办公区与公共区域。 | 细杆上的圆饼形吸顶机身 + 上方两道同心信号弧。 | 路径、目标 |
| `lb` | 负载均衡 / Load Balancer | M | LB | 把访问请求分发到多台后端服务器,提高可用性。 | 中心方体 + 一进三出的扇形分叉臂,末端小方块。 | 路径、防护 |
| `dns` | DNS 服务 / DNS | S | DNS | 把域名解析为 IP 地址,是几乎所有访问的第一步。 | 细高立柱托起一个带经纬线的小地球。 | 目标、路径 |

| 类型 | 名称 | 尺寸 | 缩写 | 用途 | 造型要点 | 常见角色 |
|---|---|---|---|---|---|---|
| `pc` | 台式电脑 / Desktop PC | M | PC | 员工日常办公主机,常是钓鱼、勒索的落点。 | 左侧竖立机箱 + 右侧支架显示器。 | 目标、源 |
| `laptop` | 笔记本 / Laptop | S | NB | 移动办公终端,常在外部网络与内网之间切换。 | 薄底座 + 后仰张开的屏幕,呈打开的书本角度。 | 目标、源 |
| `printer` | 打印机 / Printer | M | PR | 共享打印/扫描设备,常被忽视的联网资产。 | 矮胖方机身 + 前伸出纸托盘 + 顶部斜插纸张。 | 目标 |
| `mobile` | 手机 / Mobile Phone | S | MB | 移动终端,承载短信验证码、企业 IM 与邮件。 | 直立的细长薄片,略向后倾,顶部听筒缝。 | 目标、源 |
| `tablet` | 平板 / Tablet | S | TB | 会议/展示/移动审批终端。 | 横放大屏薄片,靠在三角支架上明显后仰。 | 目标 |
| `voip` | IP 电话 / IP Phone | S | VP | 基于网络的语音终端,常见于前台和会议室。 | 斜面楔形底座 + 横卧听筒(两端鼓包)。 | 目标 |

### 安全设备(Security)

| 类型 | 名称 | 尺寸 | 缩写 | 用途 | 造型要点 | 常见角色 |
|---|---|---|---|---|---|---|
| `firewall` | 防火墙 / Firewall | L | FW | 按策略控制网段之间的流量,是边界的第一道闸门。 | 三层错缝砖墙,砖块交错排列。 | 防护 |
| `waf` | Web 应用防火墙 / WAF | M | WAF | 在 Web 应用前检查 HTTP 请求,拦截注入、XSS 等。 | 竖立的六边形盾牌板 + 板前一个网页窗口框。 | 防护 |
| `idsips` | IDS / IPS / IDS / IPS | M | IPS | 检测(IDS)或在线阻断(IPS)可疑流量与攻击特征。 | 立杆上朝上的雷达碟面 + 中心接收针。 | 防护 |
| `bastion` | 堡垒机 / Bastion Host | M | BH | 运维统一入口,集中认证、授权与操作审计。 | 宽矮台基上的方形塔楼,顶部四角城垛,台基正面一扇门。 | 防护 |
| `honeypot` | 蜜罐 / Honeypot | S | HP | 故意暴露的诱饵系统,用来发现与记录攻击行为。 | 矮胖圆罐 + 宽口沿圆环 + 斜插的勺柄。 | 防护、目标 |
| `soc` | 态势感知 / SOC / SOC / Situational Awareness | XL | SOC | 集中采集日志与告警,分析研判与响应调度。 | 长桌面上三块弧形排列的大屏幕墙。 | 防护 |
| `vpngw` | VPN 网关 / VPN Gateway | M | VPN | 为远程用户/分支建立加密隧道接入内网。 | 低矮机身上横跨一道半圆隧道拱门。 | 防护、路径 |
| `behavior` | 上网行为管理 / Secure Web Gateway | M | SWG | 对员工上网流量做分类、审计与访问控制。 | 倒置漏斗(上宽下窄)+ 下方细出口管。 | 防护 |
| `sandbox` | 沙箱 / Sandbox | M | SBX | 在隔离环境中运行可疑文件,观察其行为。 | 敞口方箱框 + 箱内悬浮一颗小球(被观察样本)。 | 防护 |

|---|---|---|---|---|---|---|
| `attacker` | 攻击者 / Attacker | M | ATK | 外部恶意行为者的抽象,事件中的发起方。 | 兜帽式尖锥身体 + 头部圆球 + 前方一块小屏。 | 源 |

## 3. 造型规范

### 3.1 镜头
透视俯视:FOV 32°,方位角 30°,俯仰角 46°(比事件大全的正交镜头更有纵深)。剪影比对仍用正交镜头。

### 3.2 尺寸等级
| 等级 | 系数 | 用于 |
|---|---|---|
| S | 0.8 | 小型终端/单点设备(AP、手机、传感器、摄像头、POS 等) |
| M | 1.0 | 常规设备(路由器、交换机、PC、WAF、VPN 等) |
| L | 1.25 | 机柜/集群/关键设施(核心交换、服务器、数据库、防火墙、僵尸网络等) |
| XL | 1.5 | 平台级抽象(云平台、SOC、互联网) |

单元基准:节点主体占地约 2×2 网格格、高 0.8–2.4 格;组合示例中再乘 0.62。

### 3.3 模型(v2 实心低多边形)
- 材质:MeshStandard,flatShading(低多边形切面),roughness 0.42、metalness 0.12(轻微光泽),自发光 夜 0.10 / 日 0.05。
- 色调三档:**主体**=类别色;**浅色细部**(支架、刻线、天线、杆)夜 `#e9eef6` 日 `#f4f7fb`;**深色面**(屏幕/键盘)夜 `#1a2438` 日 `#25324a`。
- 圆柱/球最多 10 段,保持低多边形观感。
- 灯光:半球光 + 主方向光 + 冷色补光(`NODELIB.addLights`)。

### 3.4 标签牌(无地面底座)
- 节点上方悬浮小牌(深底白字 / 日间白底深字)。
- **v4 起不再使用地面发光方形底框**,状态改由模型描边表达。

### 3.5 分区底板 / 区域标签 / 连线
- `createZone({title,w,d,color})`:半透明底板 + 0.5 格细网格 + 紫色或灰色实线描边 + 外侧淡描边;前沿平铺大号中文区域名(`createZoneLabel`)。`zone.slot(i,n,cols)` 给出节点槽位。
- `createLink(a,b)`:绿色平面虚线(流动)+ 末端三角箭头。

### 3.6 状态(模型描边)
| 状态 | 表现 |
|---|---|
| 普通 normal | MeshStandard 常亮 |
| 选中 selected | 白色 EdgesGeometry 细描边 |
| 被攻击 attacked | 主体闪红 + 红色细描边 + 轻微抖动 |
| 已防护 protected | 青色细描边 + 薄半透明护罩 |

|---|---|---|

| 分区描边·紫 | `#8a5cff` | `#5a2fa8` |
| 分区描边·灰 | `#7a8498` | `#4f5a6c` |

## 4. 复用接口

```js
NODELIB.setTheme('dark');                       // 或 'light'
NODELIB.addLights(scene);
const n = NODELIB.createNode('firewall', { size: 1.25, badge: true });
scene.add(n.group);
n.setState('attacked');                         // normal | selected | attacked | protected
function frame(t){ n.update(t); }               // 每帧调用,t 为秒
const z = NODELIB.createZone({ title: '安全管理区', w: 10, d: 7, color: 'violet' }); scene.add(z.group);
const link = NODELIB.createLink(n1.group.position, n2.group.position); scene.add(link.group); // 每帧 link.update(t)
n.dispose();
```
返回对象还有 `bounds:{height,radius}`、`color`、`cat`。现有事件场景暂未替换为这些节点。

## 5. Unity 端
`data/nodespec.json` 含类别色、尺寸、状态色、每种节点的部件列表(shape/args/pos/rotRad,单位与 three.js 一致,Y 向上,右手坐标;导入 Unity 时 Z 取反)。Unity 工程本次未改动。
